# 정책위원회 in 홍성

2026 서울특별시사회복지사협회 정책위원회 정기회의 및 워크숍(2026. 8. 21.~22., 충남 홍성·보령) 안내 페이지.
빌드 도구가 없는 정적 페이지 한 장 + 참석 회신을 받는 Apps Script 백엔드로 구성됩니다.

```
index.html              페이지 전체 (HTML·CSS·JS 한 파일)
apps-script/Code.gs     구글시트에 붙이는 백엔드
README.md               이 문서
```

## 무엇을 하는 페이지인가

- `01 개요` · `02 참석자 현황` · `03 일정` · `04 장소` 네 항목을 한 페이지에 담습니다.
- 참석자 현황에서 각자 `수정`을 눌러 **참석 구분 · 하행/복귀 열차 · 도착 시각 · 숙소 · 티셔츠 사이즈**를 직접 입력합니다.
- 상단 `PDF 저장` 을 누르면 전체 일정이 A4 6쪽 안팎으로 출력됩니다.

## 데이터는 어디에 있나

**「참석자 명단」 구글시트가 유일한 원본입니다.**

```
참석자 명단 시트  ←→  Apps Script 웹앱  ←→  index.html
```

- 시트를 고치면 페이지가 따라옵니다. 페이지를 고치면 시트에 다시 적힙니다.
- 별도의 응답 시트를 만들지 않습니다. 시트 하나만 관리하시면 됩니다.
- `API_URL` 이 비어 있거나 연결이 끊기면 `index.html` 의 `BASE` 값이 보입니다.

Apps Script가 건드리는 열은 **참석구분 · 이동방법 · 기차시간(하행) · 기차시간(상행) · 숙소 · 티셔츠** 여섯 개뿐입니다. **연락처와 성별은 읽지도 쓰지도 않습니다.**

### 시트 값을 어떻게 읽나

머리글 이름으로 열을 찾고, 칸의 글자를 해석합니다. 띄어쓰기가 달라도 됩니다.

| 열 | 시트에 적힌 값 | 해석 |
|---|---|---|
| 참석구분 | `전일정` / `부분 참석` / `후발대 참석` / `불참` | full · day1 · late · no |
| 이동방법 | `기차(단체)` / `기차(개별)` / `자차` | 기차 · 자차 |
| 기차시간(하행) | `영등포 09:27→광천 11:36` | 출발 시각으로 편성을 찾음 |
| | `12:00 도착 예정` | 자차 도착 시각 |
| 기차시간(상행) | `광천 13:14 → 용산 15:49` | 하차역으로 판별 |
| | `홍성 잔류` / `1일차만 참석` / `자체 이동` | 개별 이동 |
| 숙소 | `7인실` / `1인실_1` / `모듈` / `-` | 방 배정 · `-` 는 숙박 없음 |
| 티셔츠 | `95` / `100` / `105` / `미정` | 사이즈 |

새로운 값을 쓰시려면 `Code.gs` 위쪽의 `DEP_TO_TRAIN`, `ROOM_ID`, `UP_TXT` 표에 추가하면 됩니다.

`메모` 또는 `비고` 열을 만들어 두면 그 내용도 함께 읽고 씁니다. 없어도 동작합니다.

### 시트 정비 도구

손으로 적다 보면 `용산18:21`, `·용산18:21`, `2일차 자차 이동` 처럼 표기가 흔들립니다. 지금 코드는 이런 것도 읽어내지만, 아예 표기를 맞춰 두면 더 안전합니다.

| 함수 | 하는 일 |
|---|---|
| `checkSheet` | 고치지 않고, 해석이 안 되는 칸만 찾아 보고합니다 |
| `normalizeSheet` | 값을 표준 문구로 다시 적고, 여섯 개 열에 **드롭다운**을 설치합니다 |
| `exportBase` | 시트 내용을 `index.html` 의 `BASE` 배열 코드로 뽑아 줍니다 |

`normalizeSheet` 를 한 번 돌리면 이후에는 드롭다운에서 고르게 되어 오타가 생기지 않습니다. 하행 열만 자차 도착 시각(`12:00 도착 예정`)을 적을 수 있게 목록 밖 입력을 허용합니다.

### 중복을 없애려면

데이터가 **시트**와 **`index.html` 의 `BASE`** 두 곳에 있습니다. `BASE` 는 시트를 못 읽을 때 쓰는 대비책이라 지울 수는 없지만, 손으로 옮겨 적을 필요는 없습니다.

```
시트 수정  →  Apps Script 에서 exportBase 실행
           →  실행 기록에 나온 BASE 배열을 index.html 에 붙여넣기  →  push
```

이러면 두 곳의 내용이 항상 같습니다. 급하지 않으면 굳이 안 하셔도 됩니다. 페이지는 어차피 시트 값을 우선하니까요.

### 확정본과 시트의 관계

`index.html` 의 `BASE` 배열이 **확정본**입니다. 시트가 비어 있으면 이 값이 그대로 보이고, 시트에 회신이 들어오면 그 사람만 시트 값으로 덮어씁니다.

그래서 확정된 내용은 시트가 아니라 `BASE` 에 박아 두는 편이 안전합니다. 시트에는 그 이후의 변경분만 쌓입니다.

시트와 `BASE` 를 완전히 같게 맞추려면 Apps Script 편집기에서 순서대로 실행합니다.

```
reset          시트의 회신을 전부 지웁니다
seedFromPage   확정본 17명을 시트에 그대로 기록합니다
```

### 값이 꼬였을 때 초기화

테스트 데이터가 섞여 값이 이상하면 아래 순서로 되돌립니다.

1. Apps Script 편집기에서 **`reset`** 실행 → 시트의 회신을 전부 지웁니다 (머리글은 남습니다)
2. 페이지에서 **`새로고침`** → 명단이 `index.html` 의 `BASE` 상태로 돌아옵니다
3. 특정 위원 한 명만 지우려면 **`removeOne(12)`** 처럼 id를 넣어 실행합니다

브라우저에 남은 미전송 입력은 페이지 상단의 **`이 기기 보관분 지우기`** 로 지웁니다. 이 버튼은 미전송이 있을 때만 나타납니다.

### 저장이 꼬이지 않는 이유

서버(구글시트)를 유일한 기준으로 둡니다.

- 저장에 **성공**하면 브라우저 사본을 즉시 버립니다. 나중에 시트를 비워도 예전 값이 되살아나지 않습니다.
- 저장에 **실패**한 회신만 브라우저에 남고, 상태칩에 `미전송 n건` 으로 표시됩니다.
- 시트를 못 읽으면 **마지막으로 받아둔 값을 그대로 유지**합니다. 확정본으로 되돌아가 화면이 널뛰지 않습니다. 이때 상태칩은 `연결 실패 · 마지막 값 표시` 가 됩니다.
- `새로고침` 을 누르면 시트 값으로 전부 다시 그립니다.

### 입력한 값이 사라질 때

원인이 세 가지였고 모두 고쳤습니다. 예전 코드를 쓰고 계시면 `Code.gs` 와 `index.html` 을 최신으로 바꿔야 합니다.

| 원인 | 증상 | 고친 방법 |
|---|---|---|
| 시트에 열차 **이름만** 저장하고 식별자를 안 남김 | 새로고침하면 열차 선택이 `열차 선택 필요` 로 돌아감 | `열차ID` 열을 따로 저장. 예전 데이터는 이름을 보고 되살립니다 |
| 열 위치를 **번호로** 찾음 | 예전 시트를 쓰면 값이 옆으로 밀려 참석여부가 `확인 중` 이 됨 | 머리글 **이름**으로 찾도록 변경. 빠진 머리글은 자동 추가 |
| 서버 응답에 없는 사람은 로컬 저장본까지 버림 | 저장이 실패한 회신이 새로고침 때 사라짐 | 서버에 없는 사람만 로컬 저장본으로 보완하고 상태칩에 `미전송` 표시 |

서버 저장이 실패하면 입력값을 브라우저에 남겨 두고 상태칩이 `저장 실패 · 미전송` 으로 바뀝니다. `새로고침` 을 누르면 다시 시도합니다.

**점검 방법** — Apps Script 편집기에서 `selfTest` 를 실행하고 실행 기록(`Ctrl+Enter`)을 봅니다.

```
왕복 확인 정상 — 값이 그대로 돌아왔습니다.
```

이 줄이 나오면 저장·조회가 정상입니다. `값이 다릅니다` 가 나오면 어느 항목이 어떻게 틀어졌는지 함께 표시됩니다. 점검 후 시트에서 `id 999` 행은 지워 주세요.

편집기에서 **`selfTest`** 를 실행하면 저장·조회가 한 번에 점검됩니다. 점검 후 시트에서 `id 999` 행은 지워 주세요.

## 내용 수정

### 명단

`index.html` 의 `BASE` 배열을 고칩니다. `id` 는 회신 저장의 기준이므로 **한 번 정한 뒤에는 바꾸지 마세요.**

```js
{id:15, name:"정순영", group:"운영위원", org:"관악구지역사회보장협의체", title:"사무국장", status:"tbd"},
```

`status` 는 네 가지입니다.

| 값 | 표시 | 색 |
|---|---|---|
| `full` | 전일정 참석 | 민트 |
| `part` | 부분 참석 | 피치 |
| `tbd` | 확인 중 | 슬레이트 |
| `no` | 불참 | 로즈 |

참석하는 분은 `transport`(기차/자차/기타) · `train`(하행 열차 id) · `back`(복귀 편성 id) · `arr`(자차 도착 예정, HH:MM) · `room`(숙소 id) · `shirt`(95/100/105) · `note` 를 함께 적습니다. 시트에 회신이 들어오면 시트 값이 `BASE` 값을 덮어씁니다.

### 하행 열차

`index.html` 의 `TRAINS` 배열이 편집 화면의 선택 메뉴와 안내 표를 함께 만듭니다.

```js
{id:"1283", grp:"l", kind:"m", name:"무궁화", no:"1283",
 from:"용산역", dep:"16:25", to:"광천역", arr:"18:55", fare:"10,400원"},
```

| 항목 | 뜻 |
|---|---|
| `grp` | `g` 전일정 단체 편성 · `l` 후발 편성 |
| `kind` | 배지 색. `g` 민트 · `s` 새마을(블루) · `m` 무궁화(피치) |
| `arr` | 후발 도착 목록의 정렬 기준이 됩니다 |

**하행은 전원 광천역 도착**입니다. 단체 편성(`grp:"g"`)은 용산 09:14 · 영등포 09:27 출발, 광천 11:36 도착입니다.

복귀는 별도의 `BACKS` 배열이 관리합니다. 전원 같은 열차(광천 13:14 출발)를 타고 **하차역만 다릅니다**.

```js
{id:"u1", train:true, from:"광천역", dep:"13:14", to:"영등포역", arr:"15:36", label:"광천 13:14 → 영등포 15:36"},
{id:"x1", label:"1일차만 참석 · 개별 귀가"}
```

`train:true` 인 항목만 열차 안내 표에 나오고, `x` 로 시작하는 항목은 개별 이동입니다.

### 현지 차량

`CARS` 배열이 차량 배차 표를 만듭니다.

```js
{id:"c1", name:"스타렉스 8인승", who:"고석우 · 이재중", seats:7, memo:"홍주살이 대여", days:"1·2일차"}
```

`seats` 는 운전자를 뺀 승객 수입니다. `0` 이면 표에 `—` 로 표시됩니다. 이동 인원(1일차 단체 열차 인원, 2일차 숙박 인원)은 명단에서 자동 계산됩니다.

### 숙소 배정

`ROOMS` 배열이 방 목록을 만듭니다.

```js
{id:"r7", name:"7인실", sex:"남"},
{id:"none", name:"숙박 없음", sex:""}
```

`sex` 는 방 단위 표시입니다. 개인의 성별을 따로 저장하지 않습니다. 방을 늘리거나 이름을 바꾸려면 이 배열만 고치면 배정 표와 선택 메뉴가 함께 갱신됩니다.

### 굿즈 티셔츠

`SIZES` 배열이 선택지를 만듭니다. 기본값은 `["95","100","105"]` 입니다. 불참으로 표시된 분은 집계에서 자동으로 빠집니다.

### 화면이 늦게 뜰 때

시트 응답을 기다리지 않고 **지난번에 받아온 값으로 먼저 그린 뒤** 뒤에서 갱신합니다. 상태칩이 `n명 회신 · 갱신 중` 에서 `n명 회신 반영` 으로 바뀌면 최신입니다. 입력 중에는 배경 갱신이 화면을 다시 그리지 않아 작성하던 내용이 사라지지 않습니다.

- **전일정** 참석자는 `grp:"g"` 중에서 **승차역**을 고릅니다 (용산역 09:14 · 영등포역 09:27).
- **후발** 참석자는 `grp:"l"` 중에서 **열차 편성**을 고릅니다 (용산 → 광천).
- 코레일 시간표가 바뀌면 이 배열만 고치면 선택 메뉴와 안내 표가 함께 갱신됩니다.

### 일정 · 장소

`index.html` 본문의 `<section id="s2">`(일정), `<section id="s3">`(장소)에서 해당 줄을 직접 고칩니다.

- 일정 항목: `<div class="ev">…</div>`
- 이동 구간: `<div class="hop car">…</div>` — 열차 구간은 `car` 클래스를 뺍니다
